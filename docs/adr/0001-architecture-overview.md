# ADR 0001: 架构概览

## 状态
已接受 (Accepted)

## 日期
2026-07-21

## 背景
需要开发一个 Pixiv 批量下载工具，支持：
- 多种内容来源（画师、搜索、排行榜、收藏、关注）
- 复杂的筛选条件
- 友好的图形界面
- 可靠的并发下载和任务管理

工具的目标用户是个人使用者，需要在易用性、功能完整性和开发效率之间找到平衡。

## 决策

### 1. 技术栈

**编程语言：Python 3.11+**
- 成熟的 Pixiv API 库生态（pixivpy）
- 丰富的异步和网络库（asyncio, aiohttp）
- 快速原型开发
- 跨平台支持

**界面：Web-based GUI (Flask + Flask-SocketIO)**
- 相比传统 GUI 框架（PyQt, tkinter）：
  - 开发效率更高（HTML/CSS/JS）
  - 实时进度推送简单（WebSocket）
  - 现代化 UI 体验（Bootstrap 5）
  - 打包后依然可以作为本地应用运行
- 相比纯 CLI：
  - 更直观的交互体验
  - 实时可视化进度
  - 降低使用门槛

**前端：Bootstrap 5 + Vanilla JavaScript**
- 不引入 React/Vue，保持简单
- Socket.IO Client 用于实时通信
- 响应式设计，适配不同屏幕

### 2. 认证方式

**选择：Refresh Token**
- 相比每次输入密码：更安全，体验更好
- 相比 Cookie 劫持：更稳定，不易过期
- 实现方式：
  - 用户首次配置时输入 Refresh Token
  - 工具自动用 Refresh Token 换取 Access Token
  - Token 加密存储到本地配置文件

### 3. 并发策略

**选择：asyncio + aiohttp 异步并发**
- 相比多线程：更高效，避免 GIL 限制
- 相比单线程串行：显著提升下载速度
- 配置：
  - 默认并发数：5-10
  - 用户可配置
  - 智能限流：检测 HTTP 429 自动降速
  - 失败重试：1s → 3s → 5s

### 4. 数据存储

**配置：YAML 文件**
- 人类可读，方便手动编辑
- 存储位置：工具目录（便携模式）

**下载历史：SQLite**
- 轻量级嵌入式数据库
- 高效查询去重
- 支持任务断点续传
- 便于统计和导出

### 5. 文件组织

**选择：按任务类型分类 + 多图作品子文件夹**

目录结构：
```
downloads/
├── artists/{画师名}_{画师ID}/{作品}/
├── search/{关键词}_{日期}/{作品}/
├── ranking/{榜单类型}_{日期}/{作品}/
└── bookmarks/{日期}/{作品}/
```

多图作品（≥2 页）自动创建子文件夹：
```
作品ID_标题/
├── p0.jpg
├── p1.jpg
└── metadata.json
```

**理由：**
- 逻辑清晰，不同来源分开管理
- 画师作品按画师聚合，便于查找
- 多图作品集中，便于整体查看
- 避免单目录文件过多

### 6. 元数据管理

**选择：每个作品保存 metadata.json**

内容包括：
- 作品信息（ID、标题、简介、标签）
- 画师信息（ID、名称）
- 统计数据（收藏数、浏览数）
- 下载信息（时间、来源任务）

**理由：**
- 便于本地检索和重新组织
- 作品删除后仍保留完整信息
- 与文件存储在一起，便于迁移
- 支持数据分析和统计

### 7. 动图处理

**选择：三种格式可叠加选择**
- 原始 ZIP：保留完整信息
- GIF：通用格式，但体积大
- MP4/WebM：高质量，需 ffmpeg

**实现：**
- 用户可同时勾选多个选项
- 检测 ffmpeg 可用性
- 缺少 ffmpeg 时提示安装

### 8. 打包分发

**选择：PyInstaller 单文件可执行程序**
- 双击即用，无需安装 Python
- 便携模式：所有数据在程序目录
- 自动启动本地 Flask 服务器
- 自动打开浏览器

**启动流程：**
1. 加载/创建配置文件
2. 启动 Flask 服务器（localhost:5000）
3. 自动打开浏览器（带随机 token）
4. 可选托盘图标

## 组件职责

### Flask Web 服务器
- 处理 HTTP 请求（创建任务、查询状态、修改配置）
- 提供静态资源（HTML/CSS/JS）
- WebSocket 实时推送进度更新

### 任务管理器
- 维护任务队列和状态机
- 协调任务执行（一次只运行一个任务）
- 处理暂停/恢复/取消操作

### asyncio 事件循环
- 管理并发下载协程
- 控制并发数（Semaphore）
- 实现智能限流和重试

### 数据层
- **SQLite**：任务历史、下载记录、去重判断
- **YAML**：用户配置、Token、偏好设置
- **文件系统**：图片文件、元数据 JSON

## 数据流

### 创建下载任务
```
用户 → Web UI → Flask 路由 → 任务管理器 → 数据库 (创建任务记录)
                                     ↓
                            任务队列 (PENDING)
```

### 执行下载
```
任务管理器 → 启动 asyncio 事件循环
    ↓
获取作品列表 (Pixiv API) → 数据库查询 (去重)
    ↓
创建下载协程 (Semaphore 控制并发)
    ↓
下载文件 (aiohttp) → 保存到文件系统 → 写入元数据 JSON
    ↓
更新数据库 (下载记录) → SocketIO 推送进度 → Web UI 更新
```

## 约束和限制

### 技术约束
- **单用户**：只支持本地单用户使用，不是多用户服务器
- **单任务**：一次只执行一个下载任务（避免资源冲突）
- **依赖 ffmpeg**：动图转视频功能需要外部 ffmpeg

### API 限制
- Pixiv API 有请求频率限制
- 需要智能限流避免被封 IP
- 某些内容需要账号年龄验证

### 功能边界
- **第一版不包含**：
  - 自动监控关注画师新作（仅手动检查）
  - 搜索高级选项（第二阶段功能）
  - 多任务并行执行
  - 远程访问或多设备同步

## 后果

### 正面影响
- **开发效率高**：Web 技术栈熟悉度高，Bootstrap 组件丰富
- **用户体验好**：现代化界面，实时反馈，易于上手
- **维护成本低**：Python + Flask 生态成熟，问题易排查
- **扩展性强**：后续可添加更多功能（自动监控、云同步等）

### 负面影响
- **打包体积大**：PyInstaller 打包后约 30-50 MB（可接受）
- **依赖 ffmpeg**：动图转视频需要用户额外安装（可打包进去）
- **内存占用**：asyncio + Flask 同时运行，内存占用约 100-200 MB
- **启动稍慢**：首次解压需要几秒（单文件模式）

### 风险和缓解

**风险 1：Pixiv API 变更**
- 缓解：使用成熟的 pixivpy 库，社区会及时更新
- 备选：提供 API 重试和降级机制

**风险 2：被 Pixiv 封 IP**
- 缓解：智能限流、可配置并发数、支持代理

**风险 3：打包后无法启动**
- 缓解：提供目录模式备选、详细的启动日志

**风险 4：跨平台兼容性问题**
- 缓解：使用跨平台库（platformdirs）、充分测试

## 实现路线

### Phase 1: MVP 核心功能
- 基础 Web 界面和首次启动引导
- 画师作品下载（完整筛选）
- 任务管理（暂停/恢复/取消）
- 配置和历史数据库
- 单文件打包

### Phase 2: 增强功能
- 搜索下载（第一阶段选项）
- 排行榜下载
- 书签/收藏下载
- 关注画师新作（手动检查）
- 动图处理（三种格式）

### Phase 3: 高级功能
- 搜索高级选项（第二阶段）
- 自动监控和通知
- 统计和数据分析
- 自动更新检查

## 替代方案

### 方案 A：纯 CLI
- 优点：开发快，体积小
- 缺点：对非技术用户不友好，进度反馈不直观
- **为什么不选**：目标用户需要图形界面

### 方案 B：PyQt6 桌面应用
- 优点：原生界面，性能好
- 缺点：学习曲线陡，UI 开发慢，打包体积大（100MB+）
- **为什么不选**：开发周期长，不划算

### 方案 C：Electron 应用
- 优点：Web 技术栈，界面现代
- 缺点：打包体积巨大（150MB+），Python 集成复杂
- **为什么不选**：与 Python 生态集成困难

### 方案 D：FastAPI + 前端框架（React/Vue）
- 优点：现代化技术栈，性能好
- 缺点：开发复杂度高，打包困难
- **为什么不选**：对小工具来说过于重量级
